What You Skip

省下了什麼：量化對照

這張表是「不用做清單」。每一列都是 Omnara 實際寫了、而你一行都不用寫的子系統。

Omnara 花掉的規模感你改用
機器層全套（omnarad·machinedaemon·machinepool·daemonprotocol）它最難的分散式工程：runner 子程序、lock-fd 存活證明、本地 outbox、PTY 跨平台、3 家供應商對帳@cloudflare/computer ＋ Sandbox ＋ Browser Run

What You Build

你真正要蓋的五樣東西

  • Contracts（脊椎）：`packages/contracts` 升格為正式 wire spec。每個資源帶 end_user 維度、每個 run 帶預算欄位——這是日後最難補的，day one 進去。CF 的型別不得滲入。
  • Console（動工中）：end-user 清單與用量、run 時間軸（SSE）、審批收件匣、額度與硬上限設定、憑證管理。先打 mock。
  • Runtime（`apps/runtime`，一個 wrangler 專案）：每個 (end_user, session) 一個 DO；裡面 Think＋computer Workspace＋工具集；每次模型/工具呼叫過你的「三道閘」——電表（計費）、門禁（權限）、鑰匙櫃（憑證）——然後才放行。爆額度＝DO 內直接終止 run，這是你跟所有代理型工具的分界線。
  • End-user SDK 兩隻：Server SDK（org key，開 session、發 token）＋ Client SDK（end-user 短效 token，org key 永不進前端）。從 contracts 生成再手工打磨 DX。
  • 原生工具橋接：照抄 Omnara custom-tool 形狀——工具標 ready、外部經 SubmitToolCallResult 補結果，讓客戶把自己產品的功能註冊成 agent 工具。

Sequence

建議動工順序

每一階都有一句話驗收，過了才進下一階。時程不寫死——你是一個人，順序比日期重要。

P0

Contracts 定形＋mock server先做這個

把 end_user、session、run、budget、credential、tool-policy 六個資源的 contract 用 zod/OpenAPI 定下來；一個 in-memory Hono server 照 contract 回假資料。

驗收：console 和未來的 runtime 都只 import contracts，換 base URL 即切換 mock/真後端。

P1

Console 前端邏輯你的現任務

對著 mock 做四個核心畫面：run 時間軸（SSE）、end-user 用量與硬上限、審批收件匣（allow/ask/deny）、憑證管理。這同時是產品驗證素材。

驗收：用 mock 資料能完整走一遍「end user 發起 → 燒錢 → 碰上限 → 審批」的故事。

P2

Runtime 最小可跑

`apps/runtime`：一個 DO agent＋computer Workspace＋兩三個工具（exec、web）＋SSE 回 console。電表先做「計數＋超額即停」最粗版。

驗收：console 換掉 mock 後不改一行；跑中 run 燒爆假額度時被當場終止。

P3

三道閘做實

權限 ask → durable 審批（人隔天批、run 原地續）；per-end-user 憑證注入（不經過模型）；egress allowlist v0（應用層強制，宣告格式定好）。

驗收：一個未授權工具呼叫會停在收件匣，批准後從斷點繼續。

P4

SDK＋開源故事

兩隻 SDK 打包、一個嵌入範例（假的客戶 app）、README＋deploy-to-your-CF-account 指南。這時才算「可被整合」。

驗收：陌生開發者照 README 三十分鐘內在自己的 app 跑起第一個 end-user agent。

Guardrails

護欄與不做清單

computer 是 early preview。它的 API 只出現在 `apps/runtime` 內部，永不出現在 contracts——它變版時你只改一個資料夾。
CF 正在往上爬（Flue 只是第一個房客）。你的防禦是速度＋end-user 原語深度，不是功能廣度——P0–P4 以外的每件事都是干擾。
不做：泛用管理面（AI Gateway 的地盤）、桌面 GUI computer-use（spec 本來就 beta flag）、Slack 等整合、harness marketplace（Phase 2 後置）、BYO machine。
