nimplex runtime specification

Use GoFreight's Avery/rhapsody/sandbox stack as the required reference workload, then define the modules above Cloudflare computer, including nimplex's metering, permissions, and credential controls.

2026-08-23 · Evidence: tool-rhapsody README/CLAUDE.md, poc-ai/solution_router, tool-cc-forge gf-support skills, and the missing enforcement controls. Later runtime decisions supersede this proposal.

Blue: GoFreight parity baseline Orange: Cloudflare primitives Green: our implementation; stars mark differentiation

Design Inputs

Two inputs and one boundary

Input one: parity baseline : match rhapsody's production tracking, dispatch, continuation, safeguards, and monitoring before replacing it. Input two: differentiation : metering, permissions, credentials, and egress controls they disabled or lacked ( --dangerously-skip-permissions , personal credentials, no egress controls, no meter).

Boundary : expose every capability through packages/contracts ; @cloudflare/computer /Think types belong only inside apps/runtime .

Modules

Complete inventory across six modules

M1 Triggers and routing

Parity: rhapsody JQL gating/per-ticket cursors, reviewed-at-head/cooldown, cron daemon, solution_router Lambda, CI failure routing

Capability Specification Cloudflare primitive
SDK trigger End users create sessions/send messages with short-lived Client SDK tokens; org keys stay off frontends Worker route → DO
Tracker polling Jira JQL membership/per-item cursor and GitHub PR search/reviewed-at-head/cooldown, declared in agent config Cron Trigger → polling Worker
Channel input Slack mentions bind threads to sessions; generic webhooks and CI failures replace solution_router Worker webhook route
Scheduling Declarative prompt/script cron jobs with idempotency keys Cron Triggers / DO alarms
Deduplication ★source_key Tracker/item identity maps deterministically to a Session DO to prevent duplicate work Deterministic DO naming

M2 Sessions and execution

Parity: per-item dispatch, continuation turns, deterministic resume, concurrency/status sub-caps, no-progress/stall guards, capped backoff, workspace lifecycle, claude-pty driver

Capability Specification Cloudflare primitive
Session DO One per actor/task; actors may be end users or service agents, sharing one runtime DO＋SQLite
Continuation Resume interrupted turns after deployments/crashes/evictions from checkpoints; reconnect SSE by sequence Think fibers（stash/recover）
Safeguards No-progress after N turns, wall-clock stall checks, capped backoff retries; persistent stalls enter needs-attention DO alarms
Concurrency Organization/config/status caps, corresponding to max_concurrent; queue excess work Coordinator DO counters
Workspace Declarative Git/file/skill preload synchronized across isolate/container/browser computer Workspace
Harness execution Two executor implementations: lightweight native Think, or Claude Code in Sandbox for claude-pty parity required by GoFreight's Claude Code workflows; preinstall harnesses in sandbox images Think / Sandbox
Native product tool bridge Mark custom tools ready and submit external results through SubmitToolCallResult using Omnara's interface so customers expose their own product functions Contract only

M3 Three enforcement checks ★★★

GoFreight's recorded permissions: --dangerously-skip-permissions fully enabled; credentials were engineers' acli/gh logins; no metering

Control Specification Cloudflare primitive
Metering Per-actor model, tool, and sandbox-time usage; org/config/actor USD caps; stop the active run inside the DO when exhausted ; attribution reports and rebillable exports DO interception and AI Gateway
Permissions Contract-defined allow/ask/deny enforced by the platform rather than harness flags; durable approvals via console/Slack, checkpoint continuation, and audited decisions Replace dangerously-skip with headless execution under enforceable policies DO state and fibers
Credentials Agent-specific GitHub App/Jira service/Slack bot identities and brokered user OAuth; scoped, short-lived, injected into sandbox env/bindings rather than prompts ; audit distinguishes agent from human Secrets Store＋Workers bindings

M4 Network controls ★

GoFreight review found no egress/allowlist/firewall implementation

Capability Specification Cloudflare primitive
Egress allowlist Declare allowed domains per agent config; stabilize the schema from day one so backend changes preserve customer configuration. Initially enforce through proxy env and tool checks; isolates use globalOutbound: null allowlists isolate capability＋proxy
MCP allowlist Allowed MCP endpoints with secret-reference authentication per connection —
Traffic audit Record actor/destination/volume for all egress; per-actor rate limits DO counters

M5 Observation and operations

Parity: events.jsonl/History, web monitor/needs-attention, supervisor heartbeat, doctor, status/history CLI, telemetry secret masking

Capability Specification Cloudflare primitive
Event log Append-only, strictly ordered per session; archive to R2 and mask secrets at the write boundary DO SQLite＋R2
Live timeline Resumable sequenced SSE for console and Client SDK DO WS/SSE
Needs-attention Sessions stuck in one state, overdue approvals, and repeated failures appear in the console Alarms and queries
Status API status／history machine-readable projections corresponding to rhapsody's CLI, exposed through Server SDK queries —（contract）
Health checks Doctor-style diagnostics for connections, credentials, and remaining budget —

M6 Configuration and skills

Parity: conf.yaml/Git-hosted configuration reload, masked config show, tool-cc-forge marketplace, skill mounts

Capability Specification Cloudflare primitive
Agent configtyped（contracts）、 Immutable version chain with content hashes for auditing and rollback; console edits publish a new version DO/D1
Skill mounts Declare Git/registry sources and preload Workspace; Claude Code plugin marketplace compatibility lets tool-cc-forge mount without changes computer FS priming
Secret references Configuration stores only sec_… references rather than values, corresponding to rhapsody's {exec:...} with platform management Secrets Store

Phasing

Mapping to P0–P4

Phase Specification scope delivered
P0 contracts Contracts include M1 SDK triggers, M3 enforcement, M5 status, and M6 configuration, including end_user /actor, budget, tool policy, and egress declarations
P1 console M5 timeline/needs-attention and M3 approval/budget screens against mocks
P2 minimal runtime M2 Session DO/fibers/computer, M1 SDK/cron, basic M3 counting and budget stops
P3 enforcement implementation Durable permission approvals, credential injection, egress v0, secret masking
P4 SDK and open source Native tool bridge, status API, and Claude Code plugin compatibility; afterward add tracker polling and Slack, completing GoFreight parity and the internal-fleet sales entry point
Keep the demo order. Demo 1: exhaust a fake budget and stop an active run. Demo 2: replace --dangerously-skip-permissions with a dangerous-tool approval inbox and checkpoint continuation, demonstrated against rhapsody. Both require only P2/P3.
Harness tradeoff. Claude Code parity needs containerized claude-pty, estimated an order of magnitude more expensive than native Think. It is an exception to the container-under-10% target and must be reflected in pricing and metering.
