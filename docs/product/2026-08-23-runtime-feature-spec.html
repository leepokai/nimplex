nimplex Runtime 規格

以 GoFreight 的 DIY agent 疊層（Avery＋rhapsody＋sandbox）作為「必須對齊的參照工作負載」，加上 nimplex 的三道閘差異化,逐模組定義在 Cloudflare computer 之上要蓋的完整功能。

Design Inputs

兩個輸入，一條鐵律

輸入一（parity 底線）：rhapsody 已經在生產環境做到的事——tracker 派工、續跑、防呆、監控——nimplex 不能做得比它差，否則沒有退役的理由。輸入二（差異化）：三道閘＋網控，全是他們「被迫關掉或沒有」的（--dangerously-skip-permissions、個人憑證、零 egress 控制、零電表）。

鐵律：一切能力經 packages/contracts 暴露；@cloudflare/computer／Think 的型別只准存在於 apps/runtime 內部。

Modules

六個模組的完整功能清單

M1觸發與路由

Parity 對象：rhapsody trackers（JQL gating＋per-ticket cursor、reviewed-at-head＋cooldown）、cron daemon、solution_router Lambda、CI 失敗路由

功能規格CF 原語
SDK 觸發end user 經 Client SDK 開 session／發訊息（org key 永不進前端，短效 token）Worker route → DO
Tracker 輪詢Jira（JQL membership＋per-item cursor）、GitHub PR（search query＋reviewed-at-head＋cooldown）；宣告在 agent configCron Trigger → 輪詢 Worker
Channel 接入Slack @mention → thread 綁 session（取代 solution_router）；generic webhook；CI 失敗事件Worker webhook route
排程cron jobs（prompt／script 兩種），宣告式、附冪等鍵Cron Triggers / DO alarms
去重 ★source_key（tracker＋item id）決定性對映到唯一 Session DO——跨 tracker 同項目不可能被做兩次DO 決定性命名

M2Session 與執行

Parity 對象：per-item 派工＋continuation turns＋deterministic resume、max_concurrent＋per-status sub-caps、no-progress／stall guard、capped backoff、workspace 生命週期、claude-pty driver

功能規格CF 原語
Session DO每個 (actor, 任務) 一個；actor 可以是 end user（SDK 場景）或 agent 身分（Avery 場景）——同一套 runtimeDO＋SQLite
續跑turn 中斷（部署、崩潰、驅逐）自動從 checkpoint 恢復；SSE 客戶端無感重連（序號續傳）Think fibers（stash/recover）
防呆no-progress guard（N turns 無新事件）＋wall-clock stall guard＋capped backoff 無限重試；卡死進 needs-attentionDO alarms
並發控制per-org／per-config／per-status 並發上限（rhapsody 的 max_concurrent 對等物），超額排隊協調 DO（計數器）
Workspace宣告式預載（git clone、檔案、skill 掛載），跨 isolate/container/browser 同步computer Workspace
Harness 驅動executor 介面兩個實作：(a) Think 原生（輕量）(b) Claude Code in Sandbox（claude-pty parity——GoFreight 全綁 CC，這是硬需求）；harness 預裝進 Sandbox imageThink / Sandbox
原生工具橋接custom 工具標 ready、外部經 SubmitToolCallResult 補結果（Omnara 形狀）——客戶把自家功能註冊成 agent 工具—（純 contract）

M3三道閘 ★★★

GoFreight 現況：權限＝--dangerously-skip-permissions 全開｜憑證＝工程師個人 acli/gh 登入｜電表＝不存在

閘規格CF 原語
⚡ 電表每 actor 一個錶：模型（AI Gateway 成本）＋工具＋sandbox 時間全記；美元硬上限（org→config→actor 三級）；爆表＝DO 內當場終止 run；成本歸因報表＋可轉售帳單匯出DO 內攔截＋AI Gateway
🚪 門禁工具政策 allow/ask/deny 宣告在 contract、平台強制（不是 harness 旗標）；ask → durable 審批（console／Slack 按鈕），人批後斷點續跑；審批紀錄入事件日誌。賣點句：把 dangerously-skip 換成敢開權限的 headlessDO 狀態＋fibers
🔑 鑰匙櫃agent 專屬身分（GitHub App installation token、Jira service account、Slack bot）＋per-end-user OAuth（broker）；scoped、短效、注入 sandbox env／bindings，永不進 prompt；audit 可分辨 agent vs 人Secrets Store＋Workers bindings

M4網控 ★

GoFreight 現況：零（全 org 搜不到 egress／allowlist／firewall）

功能規格CF 原語
Egress allowlistper agent-config 宣告允許網域；宣告格式 day one 定稿（之後換執行層不換格式）；v0 在應用層強制：Sandbox 內 proxy env＋工具層檢查；isolate 天生 globalOutbound: null 白名單isolate capability＋proxy
MCP allowlist可連的 MCP server 白名單＋每連線 auth 綁 secret 引用—
流量稽核所有 egress（誰、去哪、多少）入事件日誌，per-actor rate limitDO 計數器

M5觀測與營運

Parity 對象：events.jsonl＋History、web monitor＋needs-attention、supervisor 心跳、doctor、status/history CLI、telemetry secret 遮罩

功能規格CF 原語
事件日誌append-only、嚴格排序、per-session（the log is the agent）；歸檔到 R2；秘密遮罩在寫入層DO SQLite＋R2
即時時間軸SSE 串流（可續傳序號）給 console 與 Client SDKDO WS/SSE
Needs-attention卡在同狀態過久的 session／審批逾期／連續失敗——rhapsody web monitor 的對等物，做進 consolealarms＋查詢
狀態 APIstatus／history 的機器可讀投影（rhapsody CLI 的對等物）＝ Server SDK 的查詢面—（contract）
健康檢查doctor 的對等物：連線、憑證、額度餘量的自檢頁—

M6設定與技能

Parity 對象：conf.yaml＋git repo 線上設定熱載入、config show 遮罩、tool-cc-forge plugin marketplace、skill 掛載

功能規格CF 原語
Agent configtyped（contracts）、immutable 版本鏈＋內容雜湊（Omnara 形狀：審計與回滾免費）；console 編輯即發新版DO/D1
Skill 掛載宣告 skill 來源（git／registry），佈建時 prime 進 Workspace；相容 Claude Code plugin marketplace（tool-cc-forge 不用改就能掛）computer FS priming
秘密引用config 只存 sec_… 引用永不存值（rhapsody 的 {exec:...} 對等物，但平台代管）Secrets Store

Phasing

掛回 P0–P4

Phase本規格落地的部分
P0 contractsM1 SDK 觸發、M3 三道閘、M5 狀態 API、M6 config 的 wire 形狀全部進 contract（含 end_user／actor、budget、tool-policy、egress 宣告格式）
P1 consoleM5 時間軸＋needs-attention、M3 審批收件匣＋額度畫面（對 mock）
P2 runtime 最小可跑M2 Session DO＋fibers＋computer、M1 SDK 觸發＋cron、M3 電表粗版（計數＋超額即停）
P3 三道閘做實M3 門禁 durable 審批＋鑰匙櫃注入、M4 egress v0、M5 遮罩
P4 SDK＋開源M2 原生工具橋接、M5 狀態 API、M6 CC plugin 相容；之後才做 M1 tracker 輪詢＋Slack channel（GoFreight parity 的最後一塊，也是內部 fleet 銷售的敲門磚）
兩個 demo 順序不要反。Demo 1＝電表斷電（跑中 run 爆假額度被當場終止）——全生態沒人做得到；Demo 2＝「把 --dangerously-skip-permissions 換掉」（危險工具停在收件匣、批准後斷點續跑）——指著 rhapsody 的程式碼賣。兩個 demo 都只需要 P2＋P3。
Harness 現實。Claude Code parity 需要 Sandbox（container）跑 claude-pty——這條路徑的成本比 Think 原生高一個量級，電表因此更重要，也是「container <10%」原則的例外項。定價要反映。
